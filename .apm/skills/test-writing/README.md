# test-writing

AI エージェントが書くテストコードの品質を、手順とハーネスの両面で担保するスキル。

## 解決する課題

エージェントにテストを書かせると、(1) 実装の分岐を写しただけで仕様の裏付けがない大量のテスト、(2) レビュー指摘の経緯をテスト化した意味不明な不在確認、(3) エラーメッセージ全文一致のような壊れやすいアサーション、が生まれやすい。共通の原因は、テストの導出元が契約(最終仕様)ではなく実装・会話履歴・観測可能な細部に汚染されていること。

## アプローチ

「テストケースと期待値の唯一の導出元は対象の契約」を中心原理に、ケース列挙とレビューゲートを汚染のないサブエージェント(実装本体・会話の経緯を渡さない)へ必須委譲する 5 ステップの手順を定める。同梱の Stop hook(`scripts/check-test-review.sh`)が、テストファイルに未レビューの変更がある状態でのターン終了を block し、レビューゲートの実施を強制する。導入方法は SKILL.md のセットアップ節を参照。
