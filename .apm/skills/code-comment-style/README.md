# code-comment-style

コードコメントの要否と品質を「初めて読む人」基準で判定させるスキル。

## 解決する課題

コメントの価値は「そのコードを初めて読む人に何が伝わるか」で決まるが、直前まで実装していたエージェント(や人間)は意図を頭の中で補完してしまうため、不要なコメント(動作の再掲など)を必要と判断し、不足(意図・根拠の欠落)を見落とす。この判定は書いた本人には原理的にできない。

## アプローチ

書くべきコメントの類型(境界の意図・契約・Why not・触るな警告など)と書くべきでない類型を規約名付きで定義し(`references/norms.md`)、評価は必ず冷えた読み手のサブエージェントへ委譲する。根拠が確認できない情報を推測で書くことを禁止し、同梱の Stop hook がコード変更後のコメント評価(または非該当報告)の実施を強制する。
