# organize-memory

Claude Code の auto-memory (`~/.claude/projects/<スラグ>/memory/`) を整理するスキル。

## 解決する課題

auto-memory は放置すると 3 つの形で劣化する。(1) ハーネスの書式変遷で旧フォーマットのファイルが混在する、(2) 完了した作業の「未実施」記録など現実と乖離した記述が将来のセッションを誤誘導する、(3) ユーザーグローバルな事実(パッケージマネージャの好みなど)がプロジェクトごとに複製されて食い違う。しかも陳腐化の判定を AI に任せると、判断がつかないものを防御的に「残す」に倒す傾向があり、掃除が進まない。

## アプローチ

scan(同梱スクリプトで機械検出)→ 分類 → 陳腐化の能動検証 → 人間裁定 → 計画承認 → バックアップして適用、の 6 ステップ。中核は「曖昧なものを黙って残すことの禁止」— 裏取りできなかったメモリは、内容を要約して人間に提示し、削除 / 保持 / 更新の裁定を仰ぐ。削除は必ず「検証の根拠」か「人間の裁定」を伴う。ユーザースコープの事実は `~/.claude/CLAUDE.md` や rules への昇格を提案し、メモリとの二重管理を解消する(organize-claude-md と相補)。

## 使い方

```
/organize-memory                  # 現在のプロジェクトのメモリを整理
「全プロジェクトのメモリを横断で整理して」   # 横断モード(重複検出・昇格・消滅プロジェクト掃除)
```
