# Codex での待ち方

Codex にはコマンドが終わったことを知らせる仕組みがない。`wait` を実行し、終わるまで様子を見続ける。

```bash
python3 <スキルのディレクトリ>/scripts/ask.py wait --session <id> --timeout 600
```

- コマンドがすぐに終わらなくても、打ち切らずに出力の確認を続け、終わるまで待つ。人は画面で回答している
- 終了コード `3`(タイムアウト)なら、同じコマンドをそのまま実行し直す。人はまだ回答中
- `wait` は何度実行し直しても安全。実行中のコマンドを見失ったら、実行し直せばよい。
  「受け取り済みです」と言われたのに出力が手元にないときは、`history` で読み直す
- 終了コード `0` なら回答、`1` ならエラーメッセージを読んで対処する

## サンドボックスで失敗するとき

`post` はホームディレクトリの下(`~/.cache/ask-via-form/`)に状態を書き、127.0.0.1 でサーバを待ち受け、そのサーバはコマンドが終わった後も動き続ける。
サンドボックスの制限でこれができずに `post` や `wait` が失敗したら、権限の昇格を求めて実行し直す。
書き込み先だけが問題なら、書き込める場所を環境変数 `ASK_VIA_FORM_HOME` で指定してもよい(同じセッションのコマンドにはすべて同じ値を渡す)。
