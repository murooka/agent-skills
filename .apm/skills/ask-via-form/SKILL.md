# 設問をフォームで聞く

設問が多いと、人は CLI 上で設問を 1 つずつ引用して答えることになり、手間がかかるうえに設問と回答の対応がずれやすい。
このスキルでは設問をブラウザのフォームに出し、人はそこで選択肢を選んだり書き込んだりして送信する。
画面とサーバは同梱スクリプトが用意するので、AI が書くのはフォーム定義だけでよい。

## 使わない場面

- **明示的な指示がないとき。** ブラウザを開き、サーバを動かし続けるので、自分の判断では始めない。
  人からの指示、CLAUDE.md などの常設の指示、使っているほかのスキルの手順での指示は、どれも明示的な指示にあたる
- **claude.ai/code などのリモート環境で動いているとわかっているとき。** 人のブラウザからフォームに届かない。その旨を伝えてチャットで聞く

## 流れ

1. フォーム定義(JSON)を書く(後述)
2. `post` でフォームを出す。`--session` なしの `post` が新しいセッションを作り、ブラウザを開く

   ```bash
   python3 <この SKILL.md と同じディレクトリ>/scripts/ask.py post form.json                    # 最初のフォーム
   python3 <この SKILL.md と同じディレクトリ>/scripts/ask.py post form.json --session k3f9qa   # 2 つ目以降
   ```

   ファイルを作らずに標準入力から渡すなら `post -`。出力の `session:` の id はセッションの間ずっと使う。
3. **チャットには URL と設問数だけを書く**(例: 「フォームに 5 問出しました: http://127.0.0.1:…」)。
   設問の中身までチャットに書くと同じ内容を二重に出すことになり、人もどちらを見ればよいか迷う
4. `wait --session <id>` で送信を待つ。**待ち方はエージェントごとに違うので、該当するものを読む**
   - Claude Code → `references/wait-claude-code.md`
   - Codex → `references/wait-codex.md`
   - agy(Antigravity CLI) → `references/wait-agy.md`
   - それ以外 → `--timeout` をツールの実行時間の上限より短くして実行し、終了コード 3(タイムアウト)なら同じコマンドを繰り返す
5. 返ってきた回答を読んで対応する(後述)。まだ聞くことがあれば 1 に戻り、**新しいフォーム id** で `post` する
6. 聞くことがなくなり、人との認識も揃ったら `stop --session <id>` で終える

## 他のスキルの出力形式を置き換える

grilling のように「設問をこの形式でチャットに出し、回答を待て」と指示するスキルと一緒に使うときは、その出力をフォーム定義に置き換える。
1 ラウンドにどの設問を載せるか、いつ次のラウンドに進むかといった判断は元のスキルに従う。変わるのは出し方と受け取り方だけ。

| 元のスキルの出力 | フォーム定義 |
| --- | --- |
| ラウンド 1 回 | フォーム 1 つ(id は `r1`, `r2`, …) |
| 設問の前に置く説明(調べた事実、決まったことのまとめ) | `intro` |
| ❓ **Q1** - **タイトル**: 本文 | 設問の `title` と `body` |
| 本文中の選択肢(A / B / C) | `options` |
| ➡️ 推奨する回答 | 推す選択肢を `recommended`、理由を `reason` |
| 回答を待つ | `wait` |

## フォーム定義

```json
{
  "id": "r2",
  "title": "ラウンド 2",
  "intro": "調べた結果、**Codex にはコマンド終了の通知がない**ことがわかりました。",
  "questions": [
    {
      "id": "runtime",
      "title": "実行基盤",
      "body": "フォームをどこで動かすかを決めます。",
      "options": [
        {"label": "A: ローカルサーバ", "description": "Python の標準ライブラリだけで動く"},
        {"label": "B: 静的 HTML", "description": "回答を CLI に貼り戻す手間が残る"}
      ],
      "recommended": "A: ローカルサーバ",
      "reason": "セッションを続けられるのは A だけなので。"
    },
    {"title": "補足", "body": "ほかに気になる点があれば書いてください。"}
  ]
}
```

フォームの項目:

- `id` — 必須。英数字・`_`・`-`。セッションの中で一意にする
- `title` — 任意
- `intro` — 任意。設問の前に置く前置き(Markdown)
- `questions` — 必須。1 問以上

設問の項目:

- `title` — 必須
- `body` — 任意。本文(Markdown)
- `options` — 任意。`{"label", "description"}` の配列。説明が要らなければ `["A", "B"]` のように文字列だけでもよい。見出しはただのテキスト、説明は Markdown
- `multiple` — 複数選択を許すなら `true`。既定は `false`
- `text` — 自由記述欄。`"none"` / `"optional"` / `"required"` のいずれかで、既定は `"optional"`
- `recommended` — 推奨回答。`options` がある設問では推す見出し(複数選択なら配列)、ない設問では推す文章
- `reason` — 推奨の理由(Markdown)。`recommended` と一緒に書く
- `id` — 任意。省略すると出てくる順に `q1`, `q2`, … が付く

回答形式は、次の組み合わせで表す。

| 聞きたいこと | 書き方 |
| --- | --- |
| 自由記述だけ | `options` を書かない |
| 選択 + 任意の補足 | `options` を書く(補足欄は既定で付く) |
| 選択だけ | `options` + `"text": "none"` |
| 選択 + 補足を必須 | `options` + `"text": "required"` |
| 複数選択 | `options` + `"multiple": true` |

選択式でも、人は選択肢を選ばずに補足欄だけ書いて答えられる(「どれでもない」を表せる)。
`"text": "required"` は「補足を書かなければ回答扱いにしない」という意味で、送信は妨げない。書かれていなければ未回答として返る。

Markdown で使える記法は、段落(改行はそのまま改行になる)、`**太字**`、`*斜体*`、`` `インラインコード` ``、
コードブロック(```)、箇条書き(`-` と `1.`、字下げで入れ子)、リンク(`[文字](https://…)`)、表だけ。見出しや引用は書いたままの文字で表示される。

書式に誤りがあれば、`post` は画面を変えずに誤りの箇所を出力してエラーで終わる。直して出し直す。

### 送信前のフォームに設問を足す

回答を待っている間に聞きたいことが増えたら(調査の結果が届いた、など)、**同じ id で `post` し直す**。
入力途中の回答は設問 id で引き継がれ、画面には「設問が追加されました」と出る。

- 設問は末尾に足す。`id` を省略した設問の途中に挟むと番号がずれ、入力途中の回答が別の設問に付いてしまう
- 設問を消す差し替えはエラーになる。取り下げたい設問は、`intro` に「Q3 は答えなくてよい」と書く
- 送信前のフォームがある間は、別の id のフォームを出せない
- 送信済みのフォームと同じ id で違う定義を `post` するとエラーになる(同じ定義なら何も起きない)

## 回答の読み方と義務

`wait` は、人の送信 1 回分を Markdown で返す。

```
# 送信 #2: フォーム r2「ラウンド 2」

## Q1 実行基盤 — 回答(推奨どおり)
選択: A: ローカルサーバ

## Q2 画面の言語 — 回答
選択: 日本語
自由記述:
> 英語対応は後で考える

## Q3 保存先 — 保留
> Q1 が決まってから考えたい

## Q4 補足 — 差し戻し
> そもそも〜という前提が違う

## Q5 名前 — 未回答

## 全体メモ
> …

## 前のフォームでの変更

### フォーム r1 Q2 対象環境 — 回答
選択: C
変更前: 回答 / 選択: B
```

設問ごとの回答状態の扱い:

- **回答** / **回答(推奨どおり)** — 決定として扱う。推奨どおりは、人が推奨をそのまま採ったことを表す
- **保留** — まだ決まっていない。**後のフォームで出し直す**。理由に「Q1 次第」などとあれば、その前提が決まってから出す
- **差し戻し** — 回答ではなく、設問そのものへの疑問や異議。決まったことにして先へ進まない。
  **返事は次のフォームの `intro` か、出し直す設問の `body` に書き**、必要なら設問を作り直して出し直す。
  人はフォームの画面を見ているので、チャットに返事を書いても届かない
- **未回答** — 決まっていない。必要なら後のフォームで出し直す

**全体メモ** には、特定の設問に紐づかない考えや、「ここまでで十分」といったセッション全体への意向が書かれる。読み落とさない。

**前のフォームでの変更** は、人が送信済みのフォームを後から直したもの。変更前の決定をもとにすでにしたこと
(書いたファイル、後の設問の前提)を見直し、影響があれば次のフォームの `intro` で伝える。

## コマンド

| コマンド | 用途 |
| --- | --- |
| `post FILE [--session ID] [--no-open]` | フォームを出す・差し替える。`FILE` を `-` にすると標準入力から読む |
| `wait --session ID [--timeout 秒]` | 送信を 1 回分受け取る。受け取った送信は受け取り済みになり、もう一度実行すると次の送信を待つ |
| `stop --session ID [--force]` | セッションを終える。受け取っていない送信があるとエラーになる |
| `sessions` | セッションの一覧 |
| `history --session ID` | これまでの送信をすべて出し直す(受け取り済みにはしない) |
| `forms --session ID` | これまでに出したフォーム定義(JSON)をすべて出し直す。選択肢の説明や推奨など、送信には含まれない設問の中身を読み直すときに使う |

`wait` の終了コードは、`0` が送信を受け取った、`3` がタイムアウト(同じ `wait` をもう一度実行する)、`1` がエラー。

- `wait` が「開いているフォームも、受け取っていない送信もありません」で終わるのは、送信を受け取ったあと次の `post` をしていないとき。
  受け取ったはずの出力を見失ったなら `history` で読み直す
- 会話の要約などでセッション id や前の回答を見失ったら、`sessions` で id を探し、`history` で送信を、`forms` で設問の中身を読み直す
- サーバが落ちていても、次の `post` か `wait` が起動し直す。最後の操作から 24 時間たつとセッションは自動で終わる
- セッションの状態は `~/.cache/ask-via-form/<id>/` に置かれる。書き込めない環境では、環境変数 `ASK_VIA_FORM_HOME` で置き場所を変える
