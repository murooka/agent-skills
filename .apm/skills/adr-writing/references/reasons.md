# 理由の集め方と評価

理由を扱うときに読む。聞く前と、受け取ったあとの両方で読む。

## 出どころで書き方を分ける

ADR の理由は、決定者の判断である。採用の理由も、不採用の理由も、次の表に従う。

| 出どころ | 例 | 書き方 |
|---|---|---|
| 決定者が述べた | 「チームが慣れているから」 | そのまま書く |
| 決定者が「無い」と述べた | 「特に理由はない」 | 「特に理由はない」と書く |
| 決定者の発話から一意に導ける | 採用理由「運用の対象を増やさない」から、別基盤の案の不採用理由 | 書く。導いたことと導出元を添える |
| **書き手が理由を付けて提案し、決定者が同意した** | 「B を推奨します。理由は〜」に「それで」 | **聞き直さない。** 提案に同意したと分かる形で書く |
| 書き手の推測 | 背景の事実から導いた理由 | 書かない。「未確認（誰に何を聞くか）」とする |

**提案への同意は、理由を付けて提案したものにだけ成り立つ。**

| 書き手が見せたもの | 決定者の返事 | 扱い |
|---|---|---|
| 推奨と理由 | 「それで」「同意」 | 同意した理由として書く |
| 不採用とする案と、その理由 | 「それで」「同意」 | 不採用の理由として書く |
| 推奨なしの利点・欠点の表 | 「A で」 | 選択だけが取れている。理由を聞く |
| 何か | 返事なし | 同意ではない。「未確認」とする |

書き方の例:

```markdown
## 理由

提案された理由（書き込みの水平スケールをシャーディングの運用なしで得られる）に同意して選んだ。
```

同意を決定者自身の言葉のように書かない。見直す人にとって、「自分で考えた理由」と「提案に同意した」は重みが違う。

## 受け取った理由は、写さずに評価する

決定者は理由を短く言うことが多く、前提は頭の中にある。見直す人にはその前提がわからない。

**決定者が述べた採用理由について、次の 5 点を確かめ、気づいたことを返す。** 返すのは評価であって、書き換えの指示ではない。「特に理由はない」、不採用の理由、「慣れている」のように事情をそのまま述べたものは、評価で問い詰めない。そのままで見直す人の役に立つ。

### 1. 前提は正しいか。読み手に誤読されないか

理由に含まれる前提を取り出し、**その言葉のまま読んだ人が何を受け取るか**を確かめる。

**例**: 「クライアント証明書は、サービス側が業界ガイドラインに準拠するために入れた」という理由は、「社内コンソールにはガイドラインが関係ない」と受け取られてしまう。ガイドラインが求めるのは認証・アクセス制御・記録であって、証明書そのものではない。

### 2. 比べる相手は適切か

「十分」「問題ない」「過剰」は、比べる相手を決めないと意味を持たない。相手が決まっていなければ聞く。

**例**: 「一般のアプリと比べて十分」ではなく、「医療情報を扱うコンソールとして十分」と比べる。

### 3. 決定によって残るリスクは何か

選んだ選択肢でも消えないリスクを返す。書かないと、見直す人は「検討されていない」と受け取り、同じ議論をやり直す。

**例**: 「JSON Schema と互換性がある」という理由なら、変換できない検証は相手に見えないというリスクが残る。

### 4. 理由を突き詰めると、もっとよい選択肢がないか

**例**: 「1 つのミスが致命傷になる」という理由を突き詰めると、アプリの中でログインを実装するより、認証を前段のプロキシに任せるほうがよい。

出たら、選択肢として示す。

### 5. どの前提が崩れたら、見直すことになるか

決定が依存している設定、規模の想定、決定の及ばない範囲を挙げる。見直す人が最初に確かめるのはこれである。

**例**: 安全性は 2 段階認証の設定に依存する。停止前からあるセッションは停止後も残る。

## 評価の結果を ADR に書くとき

評価は提案なので、採るかどうかは決定者が決める。一方、返事を待って何も書かないと、評価したこと自体が残らない。そこで中身で分ける。

| 中身 | 返事の前に書くか | 書く節 |
|---|---|---|
| 事実、決定が依存する前提 | 書く。確認がまだであることを報告する | 背景 |
| 残るリスク | 書く。確認がまだであることを報告する | 結果 |
| リスクを小さくする手立て | 書かない。手立ては選択であって事実ではない | 返事の後に結果へ |
| 書き直した理由、比べる相手を正した理由 | 書かない。それまでは受け取った言葉のまま置く。評価を返したことの注記も本文に書かない | 返事の後に理由へ |
| 突き詰めて出た案 | 書かない。ユーザーに示す | 採用なら決定へ（元の案は代替案へ）、不採用なら代替案へ |

決定を実施すれば必ずやることは、選ぶ余地がないので「結果」に書いてよい。やるかどうかを選べるものは手立てである。
